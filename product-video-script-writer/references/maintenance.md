# 版本与文件管理

## 技能版本

`VERSION` 是当前版本号的唯一权威文件，格式为 MAJOR.MINOR.PATCH。本次开始为 1.0.0，之前的实现称“未编号基线”，不追溯编造版本。

- PATCH：措辞、引用、文档勘误及兼容修复，不改变主要创作判断或流程。
- MINOR：兼容地增加或调整创作方法、审稿标准与能力。
- MAJOR：改变输入输出契约、工作流门或需要历史数据迁移的不兼容变更。

每次修改先检查现版本、适用规则、Git 差异与安装入口；版本号和 CHANGELOG 同步更新。记录日期、改动、兼容性、实际验证及限制。技能版本、JSON schema_version、候选 Vn、Word Vn 分开管理。

内部新候选包记录 `skill_version` 和 `batch_revision` 便于追溯；旧候选没有这些字段时保留原状，不能补标为新技能生成。

## 文件归属

- SKILL.md 放现役入口与关键边界，references 放按需加载的创作和契约说明。
- scripts、agents、tests 保留各自用途；CHANGELOG 放版本历史，tests/evidence 放可复核的验证记录。
- docs/archive 只放确有保留价值的历史建设记录，不作为当前状态入口。过时的 PROGRESS/BLOCKED 等完成态记录先合并归档，再移除旧入口，检查全部引用。
- 不建立 skill-v1、skill-v2 等并排安装副本，不在技能目录放用户聊天原文、产品资料、候选或正式 Word。
- 当前项目内容库按产品及产品资料、研究记录、候选文案、正式交付分类。沿用项目已定路径、命名和追加台账；无约定时用 `YYYYMMDD_产品名_内容类型_Bnn_Vn`，稳定候选 ID 配合明确的版本定位。
- 历史候选、确认事件、用户原始资料保留可追溯性；新候选取代旧稿不意味着旧稿可删。临时渲染、缓存和一次性调试产物在用途结束后按当前授权清理。清理先核对绝对路径和引用，不碰无关改动。

## 每次迭代的收尾

1. 阅读用户原话，明确本次要改变的行为，区分项目约束与可复用技能规则。
2. 修改最少的现役入口和引用；用真实失败样例或有代表性的场景检查新规则是否改变了判断，避免只检测关键词。
3. 跑 skill validator 和受影响的现有测试；创作标准发生变化时做独立情境审查，记录实际产出、发现和限制，不宣称稳定爆款。
4. 核对 VERSION、CHANGELOG、文档链接和安装入口内容一致；更新直接受影响项目的当前状态，不改历史产物。
5. 查看范围内残留、清理获准的无用文件，保留历史证据。Git 只处理已核准的相关路径；本地更新不等于提交、推送或远端发布。
