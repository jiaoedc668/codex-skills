# 任务范围与发布包装

本文件处理已有正文的标题、发布介绍和局部改稿；新候选按 SKILL.md 研究与创作。抖音和视频号均可按用户要求处理，不臆断某平台一定偏好温和开头、固定时长或特定标题。

## 最小必要输入

先使用对话中已给正文或明确指向的本地源文件。只给旧标题、不见正文时，不能确认强标题是否兑现；说明缺少正文，请用户补充。参考附件不存在或无法读取时明确指出，不把模型常见风格冒充附件特征。已提供的信息不重复询问。

阅读聊天参考时区分用户请求、用户明确评价、模型建议、客观发布数据；模型写的稿与自评不能自动升级成人物事实、偏好或direct_shoot。无用户反馈依据的推断不写台账；基于真实泛认可及当前稿提炼的机制，可按feedback-loop.md另存preserve，标为系统提炼、待复验，与user_quote分开。

## 标题与发布介绍

标题在内部比较适合本稿的切入角度，挑一个最有利害或悬念且能兑现的版本。用户未要求备选时只交一个；不机械凑标题数量。首句若不能接住更强标题，则降低标题承诺；只改标题的授权不包含顺手改开头。

只改剧情标题同样执行 [标题压缩审读](writing-style.md)：通常只表达一个主要冲突，优先人物关系加反常行为或结果；删去不影响理解的背景数字、时间和解释。约8～14个中文字只是创作参考，必要数字或身份可更长，不设字符数完整性门。短例见 [现役创作校准](creative-quality-calibration.md)，纯标题任务只读其中相关部分，不加载历史v5正例。

例如正文只支持“学一个整理资料的工具能少熬夜”，标题不能宣称“不学AI马上失业”。力度来自具体代价和反差，不来自新增预测。

发布介绍用一小段话交代议题、正文判断或观众关切，避免把完整脚本再抄一遍。标签只覆盖正文主题、目标人群及已授权IP名称，不凭空贴热点、收益、官方身份等标签。用户只要介绍就不附整套拍摄方案。

纯包装直接基于正文交付，无需新建选题池、三条候选、研究目录、最终编号或Word。不写入候选script.title的发布标题，不改变candidate_doc哈希；如果用户要把成片标题正式写回候选或Word，应保存新revision并使旧确认失效，重新走当前内容确认门。

## 局部修改与续写

限定改稿先标清保留段与可改段。只改结尾就不重做已认可铺垫，不以整批失败规则扩大范围。无法在范围内消除矛盾时解释具体冲突，不静默扩写。

沿原题修订可引用仍能支持当前事实的原研究包；事实证据失效或用户明确要求重新研究时补相应来源。普通常青虚构剧情不因原高赞样本不足停改。换题、替换核心因果或新写续篇属于新候选，按研究分流判断，再走 Raw Draft → Creative Review → 结构化；不再一律要求三条高赞来源。局部修改只在授权段内自由试写和审读，不借 Raw Draft 扩大范围。

参考续写先提炼原稿可观察的开场、推进、语气和收尾，区分用户要求保留的部分；只学机制，不同题换皮，不复制连续对白、独特金句或未经确认的第一人称履历。
