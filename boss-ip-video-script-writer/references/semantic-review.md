# 真人优先创作审读与历史机制边界

Raw Draft 后先做 Creative Review，正式候选生成前再通读一次。先问“这个人会不会这么说”“人在这个情绪里真的会说这句话吗”“是不是作者借人物的嘴在总结”“是在解决当前问题，还是只给观众解释主题”，再判断逻辑。逻辑正确但不像人话就重写；观点高级但现场不会说就重写；主要用来解释主题就优先删除或改成角色行为。

最终集中回答五问：我为什么要继续看？谁让我生气、心疼或好奇？双方为什么都不愿退？发哥说出了哪层别人没有说出的东西？最后谁的下一步发生变化？口播对应现实反驳和听众可改变的选择，不硬造现场双方。前3秒、演员口语和事件内生结尾的方法见 writing-style.md。

这是一轮模型级创作审读，不增加评分、审稿包、角色结论、schema字段或强制隔离审稿；Raw Draft 不公开。结构正确但平淡、角色像作者传声筒都属于创作失败，返回故事本身修订，不能补JSON掩盖。

旧版隔离语义审稿、公开审稿包、角色结论和汇总字段已退出生产，不再用于新候选、精修或 Word 门控。本文件仅保留该退役事实，供读取旧工件时识别来源。

当前生产候选统一使用 schema v6，schema v5保留历史兼容。单稿由 `check_candidate_integrity.py` 检查事实边界、人物引用、剧情或口播合同与客观边界；三稿由 `check_batch_integrity.py` 检查批次一致性、选题对应和因果骨架复用；历史重复由 `check_content_similarity.py` 检查。

这些命令只输出 `INTEGRITY PASS/FAIL`，不产生人工质量结论，也不能代替谢总对完整候选的明确评价。
