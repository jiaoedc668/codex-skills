# 真人优先创作审读与历史机制边界

Raw Draft 后先做 Creative Review，正式候选生成前再通读一次。先问“这个人会不会这么说”“人在这个情绪里真的会说这句话吗”“是不是作者借人物的嘴在总结”“是在解决当前问题，还是只给观众解释主题”，再判断逻辑。逻辑正确但不像人话就重写；观点高级但现场不会说就重写；主要用来解释主题就优先删除或改成角色行为。

最终集中回答五问：我为什么要继续看？谁让我生气、心疼或好奇？双方为什么都不愿退？发哥说出了哪层别人没有说出的东西？最后谁的下一步发生变化？口播对应现实反驳和听众可改变的选择，不硬造现场双方。前3秒、演员口语和事件内生结尾的方法见 writing-style.md。

这是一轮模型级创作审读，不增加评分、审稿包、角色结论、schema字段或强制隔离审稿；Raw Draft 不公开。结构正确但平淡、角色像作者传声筒都属于创作失败，返回故事本身修订，不能补JSON掩盖。

## 剧情核心判废：去作者感、去导师感

老板 IP 不是负责讲大道理，而是负责帮普通人把一件复杂的事想明白。删掉人物名仍像公众号文章、情感主播或咨询师总结，便返回对白修订。尤其检查“朋友提问题→发哥完整分析→朋友继续递问题→再次分析→懂了→金句”是否在替作者授课；个别故事确有必要可以成立，不能成为默认模板。

逐句做删除测试：现实聊天真的会完整说出来吗？是在处理眼前难题还是向观众解释？人物是不是突然知道作者掌握的全部信息？一个事实、一句原话或一个反问能否替代这段解释？主要为讲全道理服务的段落优先删、缩或改为交锋，不把完整分析拆行蒙混过去。发哥一次回应原则上只做一个主要动作，一篇通常最多一次相对完整的观点表达。

教程检测看整段在做什么：若开始连续讲职业规划、债务协商、关系咨询或三步方案，收回到一个改变判断的核心问题和一个现实下一步。只有剧情中的新阻力确实需要更多信息才展开，不把方法正确当成留下整套 SOP 的理由。

表达与结尾一起审：按 writing-style.md 的70/30启发保留最强传播句，其余说大白话；不做比例统计、关键词数量统计或“懂了/明白了”程序黑名单。情绪触发优先来自冲突方现实原话，动机不能靠纯坏人兜底。结尾既要事件内生，也要检查重复金句和过度收口；看清代价不等于认同发哥，不要求完成教育闭环。替换机制见 [现役创作校准](creative-quality-calibration.md)。

## batch Creative Review：叙事与推进差异

多篇 Raw Draft 在结构化之前连读；保留既有题材与因果差异审读，再比较开场发动、关键信息揭示时机、发哥进入判断的时机、对方是否认同、最后停在哪里及收尾方式。用当前对白确认差异，不用给稿子贴“悬念型”等标签证明差异，也不新增表格或字段。

三篇若都靠朋友分次递题、发哥逐段分析、朋友接受方案来推进，即使题材不同也退回重搭相似段落。只换开头无效；还要检查判断是否总在同一位置出现、结尾是否人人认同或人人金句。允许结果先行、情绪先行、冲突直给、争论等自然机制，不设各占一种的配额，也不禁止同母题、同场景或轮流说话。

标题另做压缩审读，删背景后能否保留一个可兑现的主要冲突，标准见 [writing-style.md](writing-style.md)。这些判断只由模型语义审读负责；Python 仍只检查确定性合同与完整性。

## 历史机制与机器职责

旧版隔离语义审稿、公开审稿包、角色结论和汇总字段已退出生产，不再用于新候选、精修或 Word 门控。本文件仅保留该退役事实，供读取旧工件时识别来源。

当前生产候选统一使用 schema v6，schema v5保留历史兼容。单稿由 `check_candidate_integrity.py` 检查事实边界、人物引用、剧情或口播合同与客观边界；三稿由 `check_batch_integrity.py` 检查批次一致性、选题对应和因果骨架复用；历史重复由 `check_content_similarity.py` 检查。

这些命令只输出 `INTEGRITY PASS/FAIL`，不产生人工质量结论，也不能代替谢总对完整候选的明确评价。
